The attack prevalence differs between the supplied training and testing splits. This is an important dataset characteristic and a threat to simple interpretation; it is explicitly discussed rather than silently rebalancing the official test set.

## Preprocessing

- Numeric features: median imputation followed by standardisation.
- Categorical features: most-frequent imputation followed by one-hot encoding.
- Preprocessing was fitted within each model pipeline on training data only.
- Unseen test categories were handled with `handle_unknown="ignore"`.
- The official test split was not used for hyperparameter tuning.

No missing values were found in either CSV, but the imputation steps remain in the reusable pipeline for robustness.

## Models and commands

### Logistic Regression

- `class_weight="balanced"`
- `max_iter=1500`
- `solver="liblinear"`
- `random_state=42`

Command:

```bash
python -m nids.train --data-dir data/raw --output-dir results --models logistic_regression
```

### Random Forest

- `n_estimators=40`
- `max_depth=16`
- `min_samples_leaf=4`
- `class_weight="balanced_subsample"`
- `n_jobs=2`
- `random_state=42`

Command:

```bash
python -m nids.train --data-dir data/raw --output-dir results --models random_forest
```

The Random Forest was deliberately bounded to 40 trees and depth 16 for a practical, reproducible first baseline. It is not a hyperparameter-optimised final model.

## Initial interpretation

On this supplied test split, the 40-tree Random Forest baseline scored higher than Logistic Regression on each reported metric. Its attack F1-score was 92.08%, compared with 86.17% for Logistic Regression. Its false-positive rate was 16.67%, compared with 28.11%.

The Random Forest produced 4,232 fewer false positives and 1,758 fewer false negatives than Logistic Regression on this test set. These are descriptive comparisons for this benchmark split, not proof of generalisation to live networks.
